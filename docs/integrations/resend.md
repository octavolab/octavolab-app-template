# Resend (email)

| Item | Value |
|---|---|
| Adapter | `packages/integrations/src/resend.ts` (`ResendMessaging`, implements `MessagingProvider`) |
| API | `POST https://api.resend.com/emails` (JSON, `Authorization: Bearer <RESEND_API_KEY>`, optional `Idempotency-Key`) |
| Selected when | `MESSAGING_MODE` (default `INTEGRATIONS_MODE`) is `sandbox` or `live`; then `MESSAGING_PROVIDER=resend` is required. `fake` (default) uses the fake adapter |
| Env | `RESEND_API_KEY` (`re_...`), `MESSAGING_FROM` (`noreply@domain` or `Name <noreply@domain>`; on `APP_ENV=staging` it defaults to `OctavoLab Staging <noreply@24hcargo.com>`), optional `MESSAGING_ALLOW_LIST` (sandbox only); the API and worker refuse to start without the required ones |
| Sender domain | `24hcargo.com`, verified in Resend (region eu-west-1), DNS at GoDaddy |
| Docs read | https://resend.com/docs/api-reference/emails/send-email and /errors (re-read on the day the key is loaded, N02) |

## Behaviour
- One HTTP attempt per send with a 10 s timeout (`AbortSignal.timeout`). Retries, backoff and dead letter belong to the outbox
  worker, so a slow provider never multiplies inside one 60 s claim lease.
- Provider idempotency: the outbox passes `outbox:<eventId>`; a retry after a timeout that actually succeeded is not sent twice
  (Resend keeps keys for 24 hours; after that a very late retry could send again, which is acceptable for ops notifications).
- Sandbox never emails arbitrary people: every recipient becomes `delivered@resend.dev` (Resend's test inbox) unless it already
  ends in `@resend.dev` (`bounced@resend.dev` and `complained@resend.dev` simulate failures) or is listed, exactly
  (case-insensitive), in `MESSAGING_ALLOW_LIST` (comma-separated). Use the allow list for team addresses only, e.g. Jaime's own
  inbox on staging (`OPS_EMAIL` set to that address then receives the real order notifications). It is rejected in `live`,
  where every recipient is real.
- Templates are code (`templates.ts`): data values are HTML-escaped and stripped of line breaks; an unknown template is a
  permanent error.

## Error mapping (`MessagingError`)
| Provider answer | `code` | Outbox behaviour |
|---|---|---|
| 400, 404, 422 (validation, bad idempotency key) | `rejected` | dead-letter at once (`retryable=false`) |
| 409 `invalid_idempotent_request` (same key, other payload) | `idempotency` | dead-letter at once |
| 409 `concurrent_idempotent_requests` | `idempotency` | retry with backoff |
| 401, 403 (missing or invalid key) | `auth` | retry with backoff (fixing the key lets the event go out) |
| 429 (rate limit or quota) | `rate_limited` | retry with backoff |
| 5xx, timeout, network error, 2xx without id | `provider_unavailable`, `timeout`, `network`, `bad_response` | retry with backoff |

Error messages are `resend <status> <error name>` only: never the API key, the recipient or the provider's free-text message
(which can echo the address). `lastError` on the outbox row and the worker logs therefore hold no secrets or personal data.

## DNS for `24hcargo.com` (already published at GoDaddy)
The values are generated by Resend for this domain: copy them from Resend → Domains → `24hcargo.com`, never from memory. This
table records which records exist and why, so a DNS change does not silently break sending.

| Name | Type | Purpose |
|---|---|---|
| `resend._domainkey.24hcargo.com` | TXT | DKIM public key; Resend signs every message with the matching private key |
| `send.24hcargo.com` | CNAME | return-path (bounce) subdomain used by Resend's sending infrastructure; aligns SPF |
| `rsend.24hcargo.com` | CNAME | second Resend sending/tracking host for the domain, as listed in the Resend dashboard |
| `_dmarc.24hcargo.com` | TXT | DMARC policy for the domain (start with `p=none` and a report address; tighten after a clean month) |

Check from any shell: `dig +short TXT resend._domainkey.24hcargo.com`, `dig +short CNAME send.24hcargo.com`,
`dig +short CNAME rsend.24hcargo.com`, `dig +short TXT _dmarc.24hcargo.com`. Resend must show the domain as **Verified** before
`live`; in `sandbox` the verified domain is what lets the allow-listed addresses receive mail from `noreply@24hcargo.com`.

## Verified
- Locally and in CI: unit tests with a mocked `fetch` (`packages/integrations/src/resend.test.ts`), adapter selection, env rules.
- Only in a real run: a send with a real key to `delivered@resend.dev` and to an allow-listed address on staging.

## Operations
- Sandbox: create a Resend API key restricted to "Sending access" for `24hcargo.com`; the adapter sends only to `@resend.dev`
  test addresses and the `MESSAGING_ALLOW_LIST` addresses.
- Live mode checklist: Jaime's approval (N07), sender domain verified in Resend (SPF, DKIM), `RESEND_API_KEY` and `MESSAGING_FROM`
  loaded as Lightsail environment variables for both the app and worker containers, first real send recorded in `docs/learnings.md`.
- Key rotation: create the new key, update the Lightsail variable, redeploy (worker picks it up), revoke the old key. Events that
  failed with 401/403 in between are retried by the outbox.
- Webhooks (delivery, bounce): not consumed yet (roadmap).
- Owner: tech lead in `OWNERSHIP.md`.
